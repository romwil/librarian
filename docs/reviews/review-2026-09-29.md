## 1. The Architectural Verdict

### Cruft (Immediate excision candidates)

- **Seven `*_progress.py` facades** still sit atop `ProgressJob` (~1.2k LOC: enrich/ingest/scan/extra_files/purge×2/split). Factory collapse from 2026-09-25 remains undone.
- **`catalog.py` grew to ~1299 lines** (was ~991) — Hall, Find, curated lists, works, media, queue, gaps, music promote. Blocks exclusive agent lanes.
- **Lexicon residue:** `librarian/web/routers/review.py:1` still says “Review bagging”; Settings maps `#bagging` → shelving for compat only (`frontend/src/lib/settingsNav.js:29`).
- **Deprecated NYT list route** still returns `"deprecated": True` (`catalog.py:579`) — delete when no client remains.

### Structural Seams (Refactor required before further feature growth)

1. **`public_work` allowlist is not end-to-end** — Hall/browse/search/work *object* are clean, but `annotate_work_files` still ships absolute `files[].path`, `POST /api/music/{id}/promote` returns the raw SQLite work, and `enrich_work` returns `updated` with `cover_path` / `folder_path`. Presentation and storage still leak at mutation edges.
2. **Cover fetch has two trust models** — manual `cover_url` is allowlisted; enrich/organize indexer and atmosphere URLs still call `download_image(..., require_safe_url=False)` (default). SSRF hardening is incomplete.
3. **`catalog.py` remains the god router** — further Hall/Find/queue growth will keep re-coupling authz, disk IO, and indexer payloads.
4. **Hall hot path still does local gap fan-out** — remote catalog HTTP was correctly deferred to `GET /api/gaps` (0.5.15), but `local_gaps` still walks every magazine/comic series name with per-series queries on every Hall paint.

- **Manual cover URL SSRF allowlist** + hop re-validation (`covers.py:37-54`, `98-141`).

## 2. Detailed Findings Register

### P3-HIGH-01 — Automatic cover / atmosphere fetch bypasses SSRF allowlist

- **Category:** Security
- **Severity:** High
- **Location:** `librarian/enrich.py:496-512` (`fetch_cover_with_fallback` / `download_image` without `require_safe_url`); `librarian/covers.py:161`, `191-196` (default `require_safe_url=False`); contrast `enrich.py:865-872` (manual metadata path correctly sets `True`)
- **The Reality:** Owner/op manual `cover_url` is allowlisted (closed P3-HIGH-03). Enrichment and organize still fetch whatever URL Hardcover / Open Library / ComicVine / indexer identity returned, with `follow_redirects=True` when `require_safe_url` is false. A poisoned or redirected metadata URL reaches LAN/cloud-metadata endpoints from the Unraid namespace. Atmosphere art (`enrich.py:512`) has the same hole.
- **Mitigation Code:**

```python
# librarian/enrich.py — apply_enrichment cover + atmosphere paths
written = fetch_cover_with_fallback(
    updated,
    data_dir,
    {"isbn": updated.get("isbn") or "", "title": updated.get("title") or ""},
    indexer_cover_url=found.cover_url,
    transport=transport,
    client=client,
    require_safe_url=True,  # was default False
)
...
data = download_image(
    found.atmosphere_url,
    transport=transport,
    client=client,
    require_safe_url=True,
)
```

Default `require_safe_url=True` on `fetch_cover` / `download_image`, or restrict non-allowlisted hosts to ISBN Open Library only. Re-validate redirect hops (already implemented when the flag is on).

### P4-HIGH-01 — Work detail `files[]` still ships absolute filesystem paths

- **Category:** Privacy
- **Severity:** High
- **Location:** `librarian/serve.py:97-125` (`annotate_work_files`); consumed at `librarian/web/routers/catalog.py:645`
- **The Reality:** `public_work` strips `folder_path` / `cover_path` from the work object (tested in `tests/test_public_work_serializer.py:106-147`), but each file row is `dict(row)` including `path` (e.g. `/data/media/books/.../Dune.epub`). Every authenticated role learns host layout; pairs with download/stream file ids for targeted probing. Hall tests never assert on `files`.
- **Mitigation Code:**

```python
_PUBLIC_FILE_KEYS = ("id", "filename", "kind", "size", "duration_seconds", "track", "disc")

def annotate_work_files(rows, on_disk):
    ...
    for row in rows:
        raw = dict(row or {})
        path = Path(str(raw.get("path") or ""))
        exists = path.is_file()
        item = {k: raw[k] for k in _PUBLIC_FILE_KEYS if k in raw}
        item["on_disk"] = exists
        item["reading_room"] = ...  # as today
        # never emit path / storage_path
        out.append(item)
    return out
```

Keep absolute paths server-side only inside `_resolve_work_file` / `_files_on_disk`.

### P2-MED-01 — Progress JSON writes remain non-atomic

- **Location:** `librarian/progress_job.py:116-129`
- **The Reality:** Still `path.write_text(...)`. Crash/power loss can tear JSON; readers reset to defaults and falsely idle a running job. Process lock does not help multi-process or torn writes. Unchanged since 2026-09-25.
- **Mitigation Code:**

tmp = path.with_suffix(path.suffix + ".tmp")
tmp.write_text(text + "\n", encoding="utf-8")

### P2-MED-04 — Audnexus SQLite cache never deletes expired rows

- **Category:** Performance
- **Severity:** Medium
- **Location:** `librarian/audnexus.py:95-124`
- **The Reality:** `get` honors `max_age` (14d) but expired rows are left in place; `set` only upserts. Under heavy identify/enrich, `audnexus_cache.sqlite` on `/config` grows without bound (new surface from 0.5.16).
- **Mitigation Code:**

```python
def set(self, key: str, payload: Any) -> None:
    ...
    conn.execute("INSERT ... ON CONFLICT ...", ...)
    # opportunistic prune (~1% of writes)
    if random.random() < 0.01:
        cutoff = time.time() - (86400 * 14)
        conn.execute("DELETE FROM audnexus_cache WHERE fetched_at < ?", (cutoff,))
    conn.commit()
```
